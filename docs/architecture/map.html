Proposed design: two clients, option A selected

1. Operational-device client

Connect CCTV, camera, local video or playback. Start monitoring and keep recent footage locally.

Device owns the Decisions API assessment and review loop. Model inference runs at OpenAI.

Browser credential transport: authenticated stateless relay. Results return to the device; no non-triggered media is retained by Lookout.

Triggered incident report + event video snippet ↓

2. Shared server

Validate device scope, create or update the incident, notify configured operators and save the event clip for private replay.

Own definitions, roles, recipients, incident state and escalation. Send assigned configuration back to operational devices.

Incident alert + replay + shared status ↓

3. Operator client

Define incidents, assign rules, configure roles and recipients. Receive alerts, replay clips, acknowledge, dismiss or resolve.

Desktop and mobile. Closing this client does not stop a separate active operational device.

Decision location

A selected: device requests and receives decisions before reporting triggers and uploading clips.

B deferred: device uploads snippets for the server to assess.

Lower latency is the intent, not a measured result. Always-on monitoring depends on an active capable device. The credential relay does not move decision ownership to the server.
