# F-APP-SHELL: Application entry and fallback

Status: implemented

Depends on: F-AUTH-ACCESS

## Behavior

The shared header mark renders the static Horizon SVG in the theme's signal color. It does not load a shader or create a WebGL canvas. The wordmark, accessible name, footprint, and favicon stay unchanged. This replaces the animated Paper Liquid Metal treatment following Ken's request to remove shaders from the in-app logo. The static mark requires no asynchronous loading state.

Action buttons share a 40-pixel minimum height, 16-pixel icons, and consistent spacing. Compact header, row, and alert-preference actions use the explicit 36-pixel size. Inline text actions keep their compact layout. Labels wrap on narrow screens; icons supplement visible labels and remain hidden from assistive technology.

Initial access and route waits use shared, labeled skeletons. List and detail placeholders reserve content space without exposing protected records. Route fallback starts after 200 ms and imposes no minimum wait. Reduced motion keeps all loading indicators static. Shared buttons support an explicit busy state. Background polling retains existing content while requests are in flight.

The public “See how it works” link scrolls to the explanation with reduced-motion support. A direct `/#how-it-works` load keeps that section in view through hydration; plain `/` starts at the hero. Selecting a camera, trigger, or context card changes the adjacent illustrative example. The hero reuses the capture station’s [source-preview frame](../../../apps/app/src/components/source-preview-frame.tsx) with an illustrative still image; two larger tilted example cards sit behind it. The footer credits Lesgo Heketon and includes an all-rights-reserved notice.

Visitors open `/` to see a public Lookout introduction, can open the existing pitch deck in a separate tab from the top navigation, and can enter the existing access flow through `/devices`. The page shows an explicitly illustrative camera scene and explains the intended camera, trigger, and incident journey without claiming that live assessment is connected. The preview panels lift gently as the visitor scrolls, while reduced motion keeps them still. Access and capture headers share the approved Horizon SVG mark; the document uses its matching favicon. Workspace members navigate between `/devices` (default), `/team`, `/triggers`, and `/incidents` using path routes, with direct links, reload, and browser history support. `?view` no longer selects a page. A shared workspace layout keeps the header, access polling, and incoming alerts mounted while child pages change, so navigation does not replay the workspace-opening state or reset alert sound opt-in. Forms and lists adapt to narrow screens. Authenticated people see onboarding or workspace access controls. Devices see their restricted authorization status and a link to local capture. Members can also open trigger configuration from the Triggers link, with exactly one current navigation destination. Unknown routes still show Not Found. This is not yet a monitoring dashboard.

Shared controls use the [interaction motion styles](../../../apps/app/src/styles.css): enabled buttons give subtle press feedback, overlays use reversible opacity/transform transitions, and new feedback appears briefly. Navigation and typing remain immediate. The active workspace underline slides between destinations in 220 ms through Motion shared layout, including browser history and incident detail navigation. Reduced motion moves it immediately. Dialogs enter in 180 ms and exit in 120 ms; menus use 120 ms. Reduced motion disables CSS animation and transitions, including existing control effects. No animation delays an action or changes focus management.

Devices separates an owner-only **This browser** card from the **Connected devices** list. The card explains local capture and preserved workspace login. Device rows pair authorization status with a primary Live view action and secondary owner-only removal. The paired-device list leads browser setup in the reading order, with a count of all registered records, including removed access. Monitoring health remains above the paired-device list. The browser card sits beside the list on wide screens and follows it on narrow screens. Raised surfaces, larger device names, icon tiles, and a blue Paired badge distinguish device identity, authorization, and actions. The layout wraps at narrow widths and reuses the shared Button and Badge components.

## Entry points

Every workspace page exposes **Switch to device mode** in the shared header. The [device-mode action](../../../apps/app/src/components/access/device-mode-action.tsx) checks F-AUTH-ACCESS remembered pairing first and opens capture directly when available. First-time owners enter a device name; unpaired operators open `/monitor` for owner-approved pairing. Header actions wrap on narrow screens. The pairing screen offers **Back to workspace** before a successful device claim. Visitors, unassigned users, paired devices, and the pairing screen do not receive the switch action.

The shared member navigation also opens `/incidents` and `/incidents/$incidentId` through the existing access gate. Devices do not receive incident response controls. [Incident routes and screens](../../../apps/app/src/components/incidents/workspace.tsx) use the existing theme, buttons, and responsive layout.

Open `/`, `/pitch-deck.html`, `/devices`, `/team`, `/join`, `/monitor`, `/device`, `/triggers`, `/incidents`, an incident detail URL, or an unknown URL. The public page links to the built pitch deck and `/devices`, and has an in-page link to the journey explanation. The paired-device capture route has its own video-led header; access routes retain the shared access header and unknown-route fallback.

## Wiring and compatibility

Member screens now mount [incoming alerts](../../../apps/app/src/components/incidents/incoming-alerts.tsx) for F-ALERT-INAPP. Visitors, unassigned users, paired devices, and pairing screens do not subscribe. The alert view and sound controls appear before each screen's content; opening or silencing never changes ownership. [Complete-screen alert tests](../../../apps/app/tests/integration/incoming-alerts.test.tsx) cover the shared shell integration. Device copy explains that pairing grants workspace access and capture must run before Live view. Authorization never claims active monitoring.

Member screens also mount [background-alert setup](../../../apps/app/src/components/incidents/push-setup.tsx) for F-ALERT-PUSH. The public manifest and root links provide Home Screen metadata. The service worker caches no authenticated pages. [Setup integration tests](../../../apps/app/tests/integration/push.test.tsx) cover consent, platform guidance, and recovery. Notification clicks use the existing protected incident URL.

The shell uses the completed account/session portion of F-AUTH-ACCESS through same-origin HTTP requests. A paired device can reach capture from its access screen; visitors and unpaired human members do not receive capture authorization. Paired human browsers can capture while retaining management access in workspace tabs. The capture screen still does not assess incidents.

## Decisions and sources

[Issue #103](https://github.com/KenEzekiel/lookout-ai/issues/103) replaces browser-wide sign-out with direct capture navigation. Header and browser-card entry reuse the same lookup and setup component. Capture adds **Return to workspace** and a separately confirmed **Forget this device** action; sign-in offers remembered-device resume. Device rows add owner-only **Reconnect** with code validation and retry. Existing loading and shared dialog/button patterns apply. See F-AUTH-ACCESS for independent account/device authorization and credential rotation. Complete-screen access tests and the updated access/typography browser journeys cover the changed entry points; per-run manual QA evidence belongs in the implementation PR.

[Issue #86](https://github.com/KenEzekiel/lookout-ai/issues/86) adds device-mode entry in the shared member header while retaining the owner-only **This browser** card introduced by [PR #84](https://github.com/KenEzekiel/lookout-ai/pull/84). Model the Domain keeps role-dependent header entry in one component using the existing `Member` shape. Both owner shortcuts use the existing activation dialog and endpoint. Owner-approved operator pairing, capture entry, and device restrictions retain their existing endpoints and permissions.

The current PR implements Ken’s approved browser-card mockup and request to restore and emphasize connected-device Live view. Existing access and peer behavior is preserved. Complete-screen access integration tests cover activation confirmation/cancellation, role restrictions, viewing entry/retry/close, and removal of viewing access after revocation. Manual QA results belong in the PR.

The shared [Button and buttonVariants](../../../apps/app/src/components/ui/button.tsx) own sizes and icon placement. [ActionForm](../../../apps/app/src/components/access/forms.tsx) requires an explicit Lucide action icon, substitutes a decorative busy icon while submitting, and inherits Button sizing. Button-like links reuse buttonVariants. This follows Kenneth's request to audit inconsistent button sizing and add action icons. A second form-only height was rejected because it caused the observed 44-pixel Reload versus 32-pixel New trigger mismatch. The typed icon prop follows Model the Domain and Type System Discipline by making form callers declare their action icon. No endpoint or permission contract changes.

The current PR implements the user’s request for app-wide loading feedback. It reuses [shared loading UI](../../../apps/app/src/components/ui/loading.tsx) and [busy buttons](../../../apps/app/src/components/ui/button.tsx) without changing backend contracts or unfinished feature status.

The current PR changes `/` from an automatic `/devices` redirect to a public introduction at the user's request for a more lively landing page. The generated camera image carries an explicit preview label because F-DETECT-REVIEW remains planned. The entry action continues to use the existing `/devices` access flow. The deck is generated from the existing pitch deck package into a static app asset before dev and production builds; the generated copy stays out of version control. [Carrier Compass](https://github.com/mikeleo03/Carrier-Compass) informed the layered depth and restrained entrance motion. The user's hero reference informed the centered headline, edge circles, upper-corner light, and overlapping example panels. Cobalt extends behind the navigation, and the graphite lower section uses the approved identity colors. Labels and headings follow [DESIGN.md](../../../DESIGN.md) sentence case and spacing preferences.

The current animation change follows Ken’s request to show navigation state sliding between destinations. It builds on PR #74’s persistent workspace layout, keeps route/session ownership intact, and uses the existing Motion dependency with reduced-motion support.

The current PR follows Arsa’s request to keep dashboard UI in a layout and replace `?view` navigation with paths. Synthesis decision: a pathless TanStack workspace parent owns the access shell and renders page content through its outlet. Member context shares the resolved actor and refresh action with Devices and Team; existing pairing, invitation, and capture entry routes retain their access gates. Keeping a separate shell in each page would continue resetting access and sound state. Fix Root Causes moved ownership to the shared route; Model the Domain replaced page booleans with typed child routes and a typed navigation table.

The merge with main preserves F-RULE-CONFIG navigation and device configuration delivery alongside the redesigned access screens.

The user approved the Horizon cobalt/graphite identity and focused access-screen mockup in the implementation conversation. This PR implements that direction while preserving the newly merged capture route. The shared identity belongs to the access shell and is reused by the capture header.
